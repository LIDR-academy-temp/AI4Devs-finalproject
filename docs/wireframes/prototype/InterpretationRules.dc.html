Interpretation Rules · roadmap, not in the MVP

The step after Matching Rules: reading each provider's original Excel directly, without the standardized template. These rules would add tables beside the matching ones without changing them.

Derived status

Status computed from several columns, e.g. Type = "Sale" AND Result = "OK" → Successful; negative amount in a refund sheet → Refund.
Condition builder: column · operator · value → status, cycle

Related rows

Rows that belong together (a reserve release listed next to its original sale; a chargeback and its fee on two rows) and how to fold them into one movement.
Grouping key · which row carries the amount · which carries the date

Reported fees

When the provider's file already states the fee per row or per batch: read it, compare with the configured fee and flag differences instead of recomputing.
Column → fee type · tolerance · warning when |reported − configured| > tolerance

How it would plug into the flow

Upload Files accepts the original workbook; Column Mapping shows a third block "Interpretation" between sheets and columns; Analysis gains one validation (reported_fee_mismatch). Nothing else in the flow changes, which is why Matching Rules was designed with account-level overrides from the start.
