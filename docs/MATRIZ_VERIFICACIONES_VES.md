## Reglas de interpretaci-n

- `DOC_ACTUALIZAR`: la evidencia disponible permite corregir una afirmaci-n documental concreta sin cambiar software.
- `DOC_ACLARAR`: la fuente debe distinguir implementaci-n observada, pol-tica, historia, propuesta y verificaci-n pendiente.
- `DOC_MANTENER_PENDIENTE`: no existe evidencia suficiente para cambiar la afirmaci-n con seguridad.
- `DOC_SIN_CAMBIO`: no se propone una correcci-n documental en este momento; la evidencia debe conservarse para el cierre formal.
- `Sugerencia futura no ejecutable` no es una tarea autorizada ni una afirmaci-n de defecto implementado.
- Los estados `Pendiente` no se convierten en cerrados por actualizar el texto de un documento.
