# Checklist de aceptación de pantalla

- [ ] Se cumple el caso de uso principal.
- [ ] La navegación mantiene el contexto y ruta de regreso.
- [ ] Se identifican acciones primarias y destructivas.
- [ ] Loading, vacío, error, éxito y permisos manejados según alcance.
- [ ] Validación conserva los datos y permite corregir.
- [ ] Teclado/tabulación y foco revisados.
- [ ] Textos accesibles y contraste revisados.
- [ ] Móvil/desktop o scaling revisados según plataforma.
- [ ] Contenido largo y extremos no rompen layout.
- [ ] Animaciones intencionales; movimiento reducido si aplica.
- [ ] Se respetó el design system y no se añadió stack innecesario.
- [ ] Build/lint/tests ejecutados o estado NO EJECUTADO declarado.
- [ ] Sin cambios fuera de alcance: BD, contratos API, seguridad, despliegues.
- [ ] Evidencia visual real o limitación explícita.

**Resultado:** APROBADO / APROBADO CON OBSERVACIONES / NO APROBADO
